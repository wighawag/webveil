# Decisions made while building default-chain-mwmbl (2026-09-30)

Recorded for the `default-chain-mwmbl` done record. The code-site ones are written in full where they apply; this note is the index.

1. **Bundled files listed one by one, not the `recipes/` directory.** `BUNDLED_RECIPE` (one path) became `BUNDLED_RECIPES` (`recipes/mwmbl.mjs`, `recipes/marginalia.mjs`), so a stray file in the package can never become an engine. Not exported from the package entry, so no public API change. Site: header of `packages/webveil/src/core/backends/searchcast.ts` ("task default-chain-mwmbl").
2. **The default chain's identity key changes** (it hashes the files and `engines`), so a 0.11 default user starts one fresh state partition; the changeset says `state clear --all` removes the old one. Alternative considered: pinning the old key, rejected because two different chains would share one partition. Site: same header.
3. **`doctor` gets a separate `defaultChain` notice** (`DEFAULT_CHAIN_NOTE`), not a rewording of `defaultBackend`: `defaultBackend` is about the backend having changed and disappears once `backend` is set, while the default chain is still in use with an explicit `backend: "searchcast"` and no engines. A notice, not a problem. It links the README anchor `#the-default-engines-and-what-recipes-add`, so renaming that heading breaks the link. Alternative considered: printing it on every search (noise). Sites: `packages/webveil/src/setup.ts` header and `DoctorResult.defaultChain`; `usesDefaultSearchcastChain` in searchcast.ts.
4. **`DEFAULT_BACKEND_NOTE` no longer names the engines** ("a bundled engine chain" instead of "a bundled Marginalia engine chain"), so it cannot go stale when the chain changes again. Site: `packages/webveil/src/core/config.ts`.
5. **pi-webveil has no README of its own**: its published README is the root `README.md`, copied at `prepack` (`scripts/copy-publish-assets.mjs`). So "the pi-webveil README" is the root README's quick start, which now says in one sentence that `pi install npm:pi-webveil` works at once, and the "floor, not the product" paragraph right below applies to both packages. Alternative considered: a separate `packages/pi-webveil/README.md`, rejected because prepack would overwrite it (it is gitignored as a generated copy).
6. **Recipe header wording.** Each bundled file is searchcast's example byte for byte except its last header paragraph ("This is an example, not an engine bundled with searchcast"), replaced by a bundling paragraph with the source commit `7b0dbde7daf7b50cf99f6b7846b75e34db18602f` (the commit that added the Mwmbl example; `marginalia.mjs` is unchanged there since the previous copy, only its recorded commit moves). A test checks each header records a 40-hex searchcast commit.
