# Decisions made while building release-workflow-oidc (2026-09-29)

Recorded for the `release-workflow-oidc` done record. None meets the ADR bar.

1. **Root `package.json` gains `"packageManager": "pnpm@11.25.0"`.** `pnpm/action-setup@v5` needs a pnpm version, from its `version` input or from `packageManager`; webveil had neither. The workspace already depends on pnpm 11 (`allowBuilds` and `minimumReleaseAgeExclude` in `pnpm-workspace.yaml`), and 11.25.0 is the version the lockfile was produced with and the one serpcast pins. Alternative: `with: version: 11` in both workflows, which leaves local and CI free to drift apart. Touches local installs too: pnpm switches to the pinned version when a different one is invoked in this repo.
2. **The local `release` script (and the root `prepublishOnly` that only it used) is retired; only `release:ci` remains.** Publishing from a laptop would bypass the OIDC trusted publisher and the provenance requirement, so the only publish path is the `release` workflow, as in serpcast. The root `prepublishOnly` never ran on a real publish anyway (the root package is private), so it went with `release`. Alternative: keep `release` for emergencies; rejected because an emergency publish from a laptop is exactly the unstamped publish this task removes.
3. **Provenance is forced with `PNPM_CONFIG_PROVENANCE: true` in `release.yml`**, copied from serpcast (its decision 1): pnpm 11 publishes natively and ignores `publishConfig.provenance`, and with the setting an unattested publish fails instead of going out unstamped.
4. **`.changeset/config.json` `access` is now `public`**, matching both packages' `publishConfig.access: public` and the fact that both are public on npm. `restricted` would have told `changeset publish` to publish scoped packages privately; both names are unscoped, so it was misleading rather than harmful.
5. **The root `preinstall` (`npx only-allow pnpm`) and `ldenv` are kept unchanged.** Checked in a fresh clone with `CI=true pnpm install --frozen-lockfile` under pnpm 11.25.0: pnpm 11 runs the root `preinstall` (silently, only-allow prints nothing on success), `npx` reaches the npm registry as the GitHub runner does, and `ldenv` builds without any `.env` file. The full `verify` gate then passed with an empty `HOME`.
6. **`test.yml` runs `pnpm format:check && pnpm build && pnpm test` as one step**, the exact `verify` string from `dorfl.json`, instead of serpcast's split steps; webveil has no extra native-library setup to put between build and test.

`pnpm pack --dry-run` (checked for both packages): `webveil` ships `dist/`, `src/`, `README.md`, `LICENSE`, `package.json`; `pi-webveil` ships the same set (its `src/index.ts` is the pi extension entry). Unchanged from today's `files`.
