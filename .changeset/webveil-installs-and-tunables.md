'webveil': minor
---

webveil is now the only thing to install. Require `serpcast` `^0.6.0`. New CLI-only setup commands (not MCP or pi tools), wrapping serpcast's `serpcast/install` entry, which only they load: `webveil install-libcurl [--proxy <url>] [--force]`, `webveil install-recipes <url|path> --sha256 <hex> [--name <set>] [--proxy <url>] [--force]`, `webveil recipes` (the installed sets) and `webveil doctor [--remote]` (the library webveil loads plus this folder's backend, redacted egress, fetch transport, engines with their recipe files and configured sets; exit 1 with the problems when unhealthy). Downloads are direct unless `--proxy` is given, never through the configured egress. Every tuning value is now a config key with an env form, validated and defaulting to the old behaviour: `maxResults`, `httpTimeoutMs`, `fetchMaxRedirects` (both `web_fetch` transports, also under a proxy egress when set), the `fetchSerpcast` section (`maxIdleSessions`, `sessionIdleMs`, `reuseConnections`, `timeoutMs`, `maxBodyBytes`), and under `serpcast`: `timeoutMs`, `maxBodyBytes`, `reuseConnections`, `keepSessions`, `idlePollMs`, `maxRequestBodyBytes`, `preflightCache`, `maxPreflightAgeS`, `maxRedirects`, `decoyRule`, `decoyGuard` as `{include, exclude}` (now replaced whole across layers), `searchcast.timeoutMs`/`maxBodyBytes` (endpoint mode) and `state.persist`/`lockStaleMs`/`lockWaitMs`. `serpcast.sessionIdleMs` must now be positive (serpcast 0.6 refuses 0). Fix messages now name `webveil install-libcurl` and `webveil install-recipes`. The README gains an Install summary, a configuration reference table and uses the webveil commands in the NixOS section.
