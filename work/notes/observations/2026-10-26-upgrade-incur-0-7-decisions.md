# Decisions made while building upgrade-incur-0-7 (2026-10-26)

Recorded for the `upgrade-incur-0-7` done record. 1 and 2 are written in full at their code site, the `Cli.create('webveil', ...)` call in `packages/webveil/src/cli.ts`; this note is the index.

1. **`--mcp` keeps direct tools** (`mcp: {tools: {discovery: 'direct'}}`). incur 0.4.15 made progressive discovery the default: `tools/list` would return `search_tools`, `get_tool_details`, `call_read_tool` and `call_write_tool` instead of `search`, `fetch` and `state_clear`, renaming every tool configured MCP clients and the README know. Alternative: adopt the new default (a breaking change, for no schema saving with three small tools). Touches: every MCP client of `webveil --mcp`; README's "`webveil --mcp` serves `search`, `fetch` and `state_clear`" stays true.
2. **incur's update check is off** (`update: false`). incur 0.4.21 added a daily, automatic check in terminal runs: a detached copy of the bin fetches `registry.npmjs.org` directly, outside webveil's egress (a Tor or proxy user would leak their address and the fact they use webveil), and writes `~/.cache/incur/updates/webveil.json`. Restores 0.4.10's behaviour (no check). Test: `never asks the npm registry for a newer version` in `packages/webveil/test/cli.test.ts`.
3. **incur's `--update` flag is left in place**, and is now listed in `--help`. It runs `npm install --global webveil@latest` through npm's own network settings, only when typed. This sits awkwardly next to `install-route-explicit-under-proxy-egress` (the install commands are refused under a proxy egress until the user names a route), which `--update` does not follow. Alternatives: intercept `--update` in `serveCli` and refuse it (a new refusal for a flag `--help` still lists, since incur prints `--update` for the root even with `update: false`); or a custom `update` provider, which re-enables the background scheduling. A human may want to reverse this; an upstream ask would be for `update: false` to drop the flag too.
4. **No direct `@modelcontextprotocol/server` dependency and no override.** incur 0.7.1 imports `@modelcontextprotocol/server/stdio` itself and pins the SDK exactly (`2.0.0-alpha.4`), so both reasons for webveil's `2.0.0-alpha.2` pin are gone; keeping it would have installed a second, unused SDK copy. The dead root `pnpm.overrides` is removed (pnpm 11 no longer warns about the `pnpm` field). Evidence: `pnpm pack` of `packages/webveil` installed with `npm install` into an empty project resolves one SDK, `2.0.0-alpha.4`, and `node_modules/.bin/webveil --mcp` answers `initialize` and `tools/list` with `fetch`, `search` and `state_clear`. There is no pack/install test in the repo (the task assumed one); this was a manual check.
5. **`incur` is pinned exactly (`0.7.1`)**, as `0.4.10` was. A `^0.7.1` range would let consumers float within 0.7; the exact pin keeps the reviewed version, matching the old house choice after a prerelease broke `--mcp`.
6. **The acceptance's `web_search` tool call is the `search` tool**: `webveil --mcp` has no `web_search` tool (that is pi-webveil's name). The new test calls `search` over a real stdio handshake against a fake SearXNG backend.
7. **Em dash**: incur 0.7.1 still hardcodes it; see `2026-10-01-incur-help-em-dash.md`'s update. Help output is unchanged.
