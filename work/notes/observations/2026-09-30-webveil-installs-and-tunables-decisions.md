# Decisions made while building webveil-installs-and-tunables (2026-09-30)

Recorded for the `webveil-installs-and-tunables` done record. Each is written in full at its code site; this note is the index. None meets the ADR bar on its own, though 1 and 2 extend ADR 0004's policy surface and a reviewer may want them there.

1. **Setup commands are CLI only** (not MCP, not pi), all four, the read-only `recipes` and `doctor` included; `--llms`/`skills add` still describe them. `--proxy` defaults to a direct download, never the configured egress. No `--dir` on `install-recipes`. `recipes` is one command, not a `recipes list` group. Site: `packages/webveil/src/setup.ts` (module header), `packages/webveil/src/cli.ts` (`CliOptions`, the bin builds `--mcp` without them).
2. **`doctor`'s rules**: healthy = impersonation active (only when the serpcast backend or fetch transport uses the library) and no problem in webveil's view; `--remote` goes through the backend `egress` for the serpcast backend, else the fetch hop's; listing a code recipe's engine name imports (runs) it, as a search does, after the trust check. Unhealthy is an incur error (exit 1) whose message carries the problems and the full report as JSON. Sites: `packages/webveil/src/setup.ts`, `describeSerpcastEngines` in `packages/webveil/src/core/backends/serpcast.ts`.
3. **Key names and placement**: top-level `maxResults`, `httpTimeoutMs`, `fetchMaxRedirects`; a new `fetchSerpcast` section for the serpcast fetch transport (not under `serpcast`, which is the search identity key); serpcast pass-throughs under their serpcast names; `serpcast.state.{persist,lockStaleMs,lockWaitMs}`; endpoint limits as `serpcast.searchcast.{timeoutMs,maxBodyBytes}`. Env: `WEBVEIL_<KEY>` in upper snake case, `WEBVEIL_SERPCAST_DECOY_GUARD_EXCLUDE` for the object form; an env switch is `true`/`false`, anything else fails validation. Sites: `packages/webveil/src/core/tunables.ts`, `packages/webveil/src/core/config.ts` (`SerpcastConfig` JSDoc).
4. **No key is kept out of the identity key**: it names both the cached instance and the state partition, and every new serpcast key is an instance option. Changing a timeout therefore starts a fresh partition. Site: `packages/webveil/src/core/backends/serpcast.ts` (header).
5. **`serpcast.decoyGuard` is replaced whole across layers** (a list and an object would otherwise merge into a mix). Site: `packages/webveil/src/core/layers.ts`.
6. **`fetchMaxRedirects` under a proxy egress**: when SET, the plain guard follows redirects itself there too (undici's own limit is a fixed 20); unset, the proxied path is exactly as before. Site: `guardEgressFetch` JSDoc in `packages/webveil/src/core/security.ts`.
7. **`state.persist: false` with `searchcast.persistProfile: true` is an error**; `state clear --all` uses the default lock times. Sites: `packages/webveil/src/core/backends/serpcast.ts`, `packages/webveil/src/core/state.ts`.
8. **`serpcast.sessionIdleMs` must now be positive** (serpcast 0.6 refuses 0 anyway). Site: `packages/webveil/src/core/tunables.ts`.
9. **Fix messages name webveil's commands** (`webveil install-libcurl`, `webveil install-recipes`, `webveil recipes`) instead of `npx serpcast ...`.

Out of scope, noticed: serpcast options webveil still does not expose as keys (`caPath`, and the library-mode searchcast `headless` and `concurrency`); serpcast's own doctor problem text says `serpcast install-libcurl` (webveil's doctor appends the webveil command).
